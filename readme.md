RISC Processor Design
📌 Project Overview

The RISC Processor Design project implements a simple 32-bit Reduced Instruction Set Computer (RISC) processor using Verilog/SystemVerilog. The processor is designed using modular hardware blocks where each module performs a specific task during instruction execution. This project helps in understanding processor architecture, RTL design, instruction execution flow, ALU operations, memory interfacing, and simulation techniques used in VLSI and FPGA design.

🎯 Project Objectives

The main objective of this project is to design and simulate a basic RISC processor architecture capable of performing arithmetic, logical, memory, and branch operations. This project also helps in learning Verilog HDL coding, processor datapath design, control signal generation, and digital system verification through simulation.

🏗️ Processor Architecture

The processor architecture consists of several important hardware modules such as Program Counter, Instruction Memory, Control Unit, Register File, ALU, Data Memory, Sign Extender, and Multiplexer. All these modules are connected together to perform complete instruction execution inside the processor.

⚙️ Processor Working Flow

The processor works in five important stages: Instruction Fetch, Instruction Decode, Execute, Memory Access, and Write Back. During Instruction Fetch, the Program Counter sends the instruction address to the Instruction Memory. In the Instruction Decode stage, the Control Unit decodes the instruction and generates control signals. In the Execute stage, the ALU performs arithmetic or logical operations. During Memory Access, data is read from or written into memory. Finally, in the Write Back stage, the result is stored back into the Register File.

📖 Supported Instructions

The processor supports different types of instructions including arithmetic instructions such as ADD and SUB, logical instructions such as AND, OR, and XOR, immediate instructions like ADDI, memory instructions such as LW and SW, branch instructions like BEQ, and jump instructions such as J. These instructions demonstrate the complete functionality of the RISC processor architecture.

🔷 ALU Module (alu.v)

The alu.v file implements the Arithmetic Logic Unit of the processor. It performs arithmetic and logical operations such as addition, subtraction, AND, OR, and XOR. The ALU receives operands from the Register File and performs the required operation based on the ALU control signal generated by the Control Unit.

🔷 Control Unit (control_unit.v)

The control_unit.v file generates all the control signals required for processor operation. It decodes the instruction opcode and controls different modules such as ALU, Register File, and Data Memory. The control signals include RegWrite, MemRead, MemWrite, ALUSrc, and Branch signals.

🔷 Register File (register_file.v)

The register_file.v file stores processor registers and temporary execution data. It allows simultaneous reading of two registers and writing into one register. During instruction execution, operands are fetched from the Register File and sent to the ALU for processing.

🔷 Instruction Memory (instruction_memory.v)

The instruction_memory.v file stores all processor instructions. The Program Counter provides the instruction address, and the corresponding instruction is fetched and sent to the processor for execution. This module acts as the instruction storage unit of the processor.

🔷 Data Memory (data_memory.v)

The data_memory.v file handles memory read and write operations during load and store instructions. During a store operation, data from the Register File is written into memory. During a load operation, data is fetched from memory and sent back to the Register File.

🔷 Program Counter (program_counter.v)

The program_counter.v file stores the address of the next instruction to be executed. After each instruction execution, the Program Counter updates the address to the next instruction location. Normally, the Program Counter increases by four because each instruction occupies four bytes in memory.

🔷 Sign Extender (sign_extender.v)

The sign_extender.v file converts smaller immediate values into 32-bit format. Immediate values used in instructions are smaller in size, so they must be extended before being sent to the ALU for processing.

🔷 Multiplexer (mux.v)

The mux.v file implements a Multiplexer which selects one input from multiple inputs based on the control signal. In the processor datapath, the Multiplexer is mainly used to select between register data and immediate values for ALU operations.

🔷 Top Module (top_module.v)

The top_module.v file is the main integration module of the processor. It connects all hardware modules together and controls the overall datapath flow of the processor. This file acts as the central processor module.

🔷 Testbench (processor_tb.v)

The processor_tb.v file is used for simulation and verification of the processor design. It generates clock and reset signals, applies test instructions, and monitors processor outputs during simulation. This file verifies whether the processor is functioning correctly.

🔷 Waveform Output

The waveform output generated during simulation shows signals such as clock, Program Counter, ALU output, register values, and memory operations. The waveform helps analyze processor timing and instruction execution behavior.
